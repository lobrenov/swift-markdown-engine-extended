# Fork ledger

Swift Markdown Engine Extended is a fork of [swift-markdown-engine](https://github.com/nodes-app/swift-markdown-engine) (Copyright 2026 Luca Chen, Apache License 2.0), from 0.13.0 (commit `d1421012aeece640e2c2e47e0e573a93cbe2a420`), and has merged each upstream release since (listed under Upstream merges). It stays under Apache-2.0 (`LICENSE`, `NOTICE`). Branch `main` mirrors upstream; `live` carries the changes below and merges each upstream release.

The package, products, module names and layout are upstream's, so upstream merges apply cleanly.

## Conflict rules
When an upstream merge touches a change, its **Conflicts** line says which version wins:
- **Fork's**: keep the fork's version, and re-apply upstream's change on top only where the fork's tests still pass.
- **Re-apply**: take upstream's version, then re-apply the fork's iOS shims over it.
- **Upstream's**: take upstream's version; the fork's tests show whether the change needs re-applying.

## Repository files
`README.md` and `CONTRIBUTING.md` are the fork's own (upstream's README covers the engine and is linked from it; upstream's contributing guide applies to branches cut from `main`). `NOTICE`, `FORK.md`, `CLAUDE.md` and `fork docs/` (the fork's own documents; drafts of upstream proposals in `fork docs/upstream/`) are the fork's and don't exist upstream. **Conflicts:** Fork's.

## Changes from upstream

1. **Alternative checkboxes.** `Parser/TaskMarker.swift` defines the accepted markers: `[ ]`, `[x]`, `[X]` plus the [Alternative Checkboxes Reference Set](https://github.com/damiankorcz/Alternative-Checkboxes-Reference-Set). As in GFM, a box follows the list marker after one to four spaces or tabs and needs a space or tab after it; the bullet and ordered-marker caret helpers read it the same way. The `.taskCheckbox` attribute holds the marker character (a `String`) instead of a `Bool`. `TaskCheckboxStyle` maps each marker to an SF Symbol, an optional tint, strikethrough, click transition and right-click menu entry. A `draw` closure, when set, draws every box (on the page and in the menu) instead of the symbols. Struck items' text is `mutedText`. The styler's `styleTaskMarker` (upstream's, shared with the list helpers off) applies the marker, the slot's width and the strike. **Conflicts:** Fork's.
2. **Checkbox size and spacing.** `TaskCheckboxStyle.sizeScale` and `contentGap` set the box size and its gap from the text. The hidden spacer after `-` is kerned so the box fits the bullet slot. **Conflicts:** Upstream's.

4. **Tab / Shift-Tab** (`Input/MarkdownListIndent.swift`). These act on every selected list line plus its children. Tab only nests an item under a previous sibling. The edits are whitespace-only and go in one undo group. On a quote line they edit the whitespace after the `>` markers, among lines at the same quote level. **Conflicts:** Upstream's.
5. **Obsidian wiki-link aliases.** `[[Target|alias]]` resolves, links and reports clicks by `Target`. Upstream treats the part after `|` as an opaque id. `WikiLinkService.LinkMetadata.escapedBar` marks a storage link written `[[a\|b]]` (a table cell's alias bar): the display name leaves the backslash out and the storage form writes it back. **Conflicts:** Fork's.
6. **Theme.** `MarkdownEditorTheme` is `Equatable` and has `selectionBackground`. The theme sets NSTextView's `linkTextAttributes` and `selectedTextAttributes`. A theme change in `updateNSView` restyles in place, so the editor isn't rebuilt. **Conflicts:** Upstream's.
7. **Bindings follow SwiftUI updates.** Upstream kept the text binding, `isWikiLinkActive` binding and `onLinkClick` from `init`. An embedder that switches documents by passing a new binding therefore had every later edit written into the first document, and the editor snapped back to the unchanged text. `NativeTextViewCoordinator.refresh` runs on every update. `publish` captures the binding and document when it schedules each async write, and drops it unless `bindingFollows` (upstream's guard, shared with iOS: no document switch pending or made). An edit counts as synced once written: writing can update the view at once, and it must find the binding still matching the last synced text rather than rebuild from it. **Conflicts:** Upstream's.

Each cell is drawn from the styler with its syntax hidden; the cell being edited is a `TableCellEditor`, a `NativeTextView` running the document's configuration without tables and embeds (and the slash menu without Table and Image: `SlashCommandState.inTableCell`), showing syntax only while it has the keyboard (`revealsSyntax`). `SlashCommandProxy` acts on the cell that has the keyboard. Dragging a grip moves it, with a `tableAccent` drop line; the header can't be dragged or passed, and each move is one undo step. Deleting a table's last row or only column removes the table. A right-click on a grip goes to `NativeTextViewWrapper.onRightClickMenu` (`RightClickMenuRequest`: `RightClickMenuItem` sections, an anchor and `close`, which drops the grip's ring): Insert above, below and Delete row; Insert left, right, Delete column and Align left, centre and right (the current one checked). A column's natural width is its widest cell on one line; the table is their sum up to the editor's width, past which columns share it in proportion, none narrower than its widest word, and the table scrolls sideways only when those minimums don't fit. The header row is bold, and `PlatformFont.named` falls back to the bold system font for `.SFNS-Bold`, which doesn't resolve by name. `MarkdownHTMLRenderer` writes a cell's line break as `<br>`. 26. **Spec** (`spec/`, `Parser/MarkdownFacts.swift`). The dialect as fixtures and data any reader can test against, in three layers (`spec/README.md`): syntax (`data/`, `grammar/`), recommended edits (`edits/`) and an optional frontmatter profile (`conventions.md`), with `host-api.md` naming the host vocabulary. `MarkdownFacts.scan(_:firstLineIndex:)` reads a body's summary, headings, tasks, links, embeds, Markdown links, tags, callouts and tables with the editor's parsers; a table cell, in a quote too, is read through `MarkdownTable`, so `\|` is a link's alias bar. Each link, embed and task box carries its range in the body (a cell's mapped back to its source), for an embedder that rewrites them. `markdownLinks` are the inline `[t](path)` links and `![a](path)` images whose destination is relative (#28), each with its path (backslash escapes resolved and percent-decoded, cut at `#` or `?`), the path as written, its range, and whether it's in `<…>`. A table cell's facts take their lines from the source row, whatever `<br>`s the cell holds. A use of a reference link or image (`[t][ref]`, `[t][]`, `[ref]`) is one too when a definition `[ref]: dest` exists, with the definition's path and range: `FactScanner` reads the definitions (labels folded, the first wins, at the start of a paragraph, list item or quoted paragraph, not in code), takes them out of the summary and the other facts, and finds the uses in the text the inline nodes leave, pairing brackets as #28 does. The inline parser doesn't draw them, since a definition elsewhere would restyle every paragraph. Tests: `SpecConformanceTests` (grammar and data) and `SpecEditConformanceTests` (edits, macOS). Every case runs; the format allows a `swift` skip with a reason. `MarkdownFacts` parses on its own (`BlockParser.computeBlocks`), leaving the editor's memo alone, and reads a paragraph that continues a list item or a quote (lazy, or indented after a blank line) as part of it. **Conflicts:** Fork's (new files).

27. **CommonMark blocks and autolinks** (`Parser/BlockParser.swift`, `Parser/MarkdownAST.swift`, `Parser/BlockLevelTokenizer.swift`, `Parser/InlineParser.swift`). The block parser reads `~~~` fences and fences indented up to 3 spaces, closed only by the opener's character at least as long; indented code (4 columns, not after a list) as `BlockNode.indentedCode`; setext headings (a paragraph and its `===`/`---` line, the line as the marker); HTML blocks (CommonMark's 7 kinds) as `BlockNode.html`, kept as source; and tables without outer pipes, whose delimiter row has the header's cell count. An edit near `~~~`, an HTML block's opener (`<` first on its line) or closer (`-->`, `?>`, `]]>`, `</script>`…), or in or beside an HTML block reparses in full. A window reparse starts from the list context before it and grows a block at a time until its last block matches the old parse; the token pass re-tokenizes every block the splice changed (`BlockParser.changedRange`). An indented line continues a paragraph, and indented lines after a list or its lazy paragraph aren't code. The inline parser reads `<scheme:…>` and `<email>` autolinks after code spans and escapes, but not a link's `](<…>)` destination, as a `.link` whose markers are `<` and `>` and whose child is its text. The styler shows indented code as code, the HTML renderer writes both blocks, and a tab-indented `***` is code, so `ThematicBreakMarkTests` and `ListParsingTests` test CommonMark's indents. Tests: the `spec/grammar` cases, `CommonMarkBlockTests`, `AutolinkTests`, and the incremental fuzz with these forms. The block parser also reads a list marker with nothing after it (`-`, `1.`) as an empty item, which can't interrupt a paragraph (`BlockParser.isEmptyListItem`). **Conflicts:** Re-apply: upstream's change first, then these rules, until upstream reads them.

28. **Inline links** (`Parser/InlineParser.swift`). `[text](destination)` and `![alt](destination)` follow CommonMark where upstream's matcher stopped at the line end and the first `]` or `)`: brackets pair innermost first, so link text holds brackets (`[a [b] c](x.md)`), an image (`[![i](p.png)](x.md)`) and a wiki link, and an unmatched `[` stays literal; the text, a title on the next line (`[a](b.md\n"t")`) and the blanks inside the parentheses may cross line endings, with a quote's `>` markers after them; the destination is one without a line ending or a bare space (`[a](My Note.md)` isn't a link; `<My Note.md>` is), with escapes (`a\(1\).md`) and balanced parens, then an optional title (`"…"`, `'…'` or `(…)`) after a blank; empty text is a link; a link holds no link (the inner one stands). Escapes and spans in a destination don't reject the link. A backslash escape inside `[[…]]` or `![[…]]` claims nothing, so those read literally (`[[Foo\_bar]]`). List items stay a line each, so a link wrapped inside one isn't read. `InlineParser.linkDestination` is what `MarkdownFacts` reads a destination with. `InlineSpanDensityTests`' fingerprint is re-recorded for the new trees. Tests: `MarkdownLinkFormTests`, the `markdown-links*` grammar cases, the fuzz in `ParseIncrementalEquivalenceTests`. **Conflicts:** Re-apply: upstream's change first, then these rules.

## Completion keys
Three pickers can be open at a caret: a slash, link, embed or tag query (#10, #20, #24), upstream's `[[…]]` / `![[…]]` preview (`isWikiLinkActive`) and upstream's directive picker (`onDirectiveCompletion`, macOS). `TextView/Coordinator/NativeTextViewCoordinator+Completion.swift` gives the keys to one of them, in that order (`completionOwner`), through upstream's `onInlinePreviewKey`, from `doCommandBy` (before a table cell's keys), ⌘↵ and, for a query only, the iOS key commands. One closure serves all three; the embedder tells them apart by `onSlashCommandChange`, `isWikiLinkActive` / `onInlineSelectionChange` and `onDirectiveCompletion`. A query's ⇥ is `.confirm`, its ⌘↵ `.confirmAndOpen` (an embedder that keeps ⌘↵ for itself returns `false`), and its esc closes it in the engine whether or not the embedder handles keys. An open query or preview also holds back the directive picker. The fork's query reports and commits keep their own types; upstream's names for the same things: `SlashCommandState` ↔ `DirectiveCompletionContext`, `onSlashCommandChange` ↔ `onDirectiveCompletion`, `SlashCommandProxy.insert` ↔ `pendingDirectiveCompletion` (`DirectiveCompletionRequest`). **Conflicts:** Fork's.
